## 结论

本地开发闭环已可复现：Alembic 迁移、幂等种子、FastAPI、Vite API 模式、公开目录和咨询提交可一起启动；咨询回执使用正式 envelope 且不回显完整联系方式。后端自动化测试为 **30 passed**，OpenAPI 3.1 静态操作覆盖运行时操作；前端默认模式和 API 模式生产构建均通过。

后台认证联调已补充验证：四个岗位智能体分别使用 `operator`、`reviewer`、`lead`、`admin` 账号和统一演示密码登录；浏览器刷新可恢复会话，退出返回登录页，各账号只显示自己的工作台导航。1440×900 与 390×844 登录页视觉检查通过，整轮浏览器控制台为 0 error / 0 warning。

这不是生产上线验收。真实模型、对象存储、XLSX、持久导出/后台任务及 PostgreSQL 生产验证仍明确排除，相关接口不会伪造成功。

## 实际执行记录

```powershell

# 30 passed, 2 dependency deprecation warnings

# 前端本地演示模式
cd prototype
npm run build

# 前端 API 模式
$env:VITE_API_BASE_URL="http://127.0.0.1:8000/api/v1"
npm run build

# 一键联调；默认 4173 当时被既有进程占用，因此改用隔离端口
.\scripts\run-local-integration.ps1 `
  -PythonExecutable "<Python 3.12 路径>" `
  -Seed -Smoke -ApiPort 18001 -FrontendPort 14174
```

一键联调结果：迁移完成；重复运行种子命令无重复；`/health/ready` 为 200；前端首页为 200；`/api/v1/config` 和 `/api/v1/tea-items` 返回 `{data,meta}`；咨询创建返回 201、正式 request ID 和脱敏回执。脚本遇到占用端口会停止并保留现有进程，不会删除数据库或终止无关服务。验收完成后仅停止了脚本创建的 Python/Node 进程，并核对 18001/14174 端口释放。

## 本地启动与停止

首次使用先安装依赖：

```powershell
cd backend
python -m pip install -e ".[dev]"
cd ..\prototype
npm ci
cd ..
```

启动：

```powershell
.\scripts\run-local-integration.ps1 -Seed -Smoke
```

脚本成功后打印用户端、管理后台、API 文档和两个准确 PID。完成后按打印的 `Stop-Process -Id <api>,<frontend>` 命令停止；脚本直接启动并记录 Python 与 Node 进程，因此不会遗留 npm 派生服务。

## 已知边界

- SQLite、演示来源、演示账号和规则问答只用于本地联调。
- 正式上线前必须验证 PostgreSQL 迁移和事务语义、HTTPS Secure Cookie、生产 CORS、密钥管理、对象存储、备份恢复与回滚。
- XLSX、公开文件、真实模型、异步导入/导出 worker 和下载授权未配置时返回显式错误或没有路由，不以假数据替代。
- 前端 API 开关目前加载公开茶品及冲泡数据；原型后台仍使用既有本地交互状态，不会自动把 localStorage 写回服务端。
