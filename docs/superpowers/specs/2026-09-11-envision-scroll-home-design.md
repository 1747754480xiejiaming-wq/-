# 茶序沉浸式滚动首页设计规格

日期：2026-09-11

## 目标

把当前连续长页面首页升级为类似远景科技集团官网的沉浸式滚动叙事：桌面端使用原生页面滚动驱动全屏 `sticky` 舞台，移动端使用全屏纵向吸附。茶的历史四个章节分别成为独立滚动场景，同时保留茶序现有内容、视觉语言、公开数据规则和页面入口。

参考站点：<https://www.envision-group.com/cn/#/>。借鉴范围为全屏固定舞台、滚动进度、叙事节奏与导航反馈；画面、文案、品牌元素和实现代码均使用茶序自己的内容。

## 信息架构

首页固定为七幕：

| 幕序 | 场景 ID | 导航归属 | 核心内容 |
|---|---|---|---|
| 01 | `home` | 首页 | 品牌主张、茶山与茶盏主视觉、搜索和问茶入口 |
| 02 | `history-origin` | 茶的历史 | 起源与利用 |
| 03 | `history-craft` | 茶的历史 | 制茶与分类 |
| 04 | `history-culture` | 茶的历史 | 茶事与交流 |
| 05 | `history-record` | 茶的历史 | 当代记录与来源可追溯 |
| 06 | `categories` | 茶叶品类 | 绿茶、红茶及当前公开档案数量 |
| 07 | `references-contact` | 参考资料与联系我们 | 资料边界、版本说明、咨询与后台入口 |

桌面顶部导航保留四项。点击“茶的历史”进入 `history-origin`，四个历史场景期间均保持该导航项高亮。现有 `?section=home|history|categories|references-contact` 链接继续有效，其中 `history` 映射到 `history-origin`。进度点提供七幕直接定位；历史四点分别带可访问名称。

## 桌面滚动模型

首页由 `ScrollStory` 管理一个约七个视口高的滚动轨道。轨道内只有一个 `position: sticky; top: 0; height: 100svh` 舞台，七个场景重叠放置。页面不拦截 `wheel`、触控板、PageDown、空格键或浏览器滚动行为。

滚动进度计算：

```text
rawProgress = clamp((scrollY - storyTop) / (storyHeight - viewportHeight), 0, 1)
sceneFloat = rawProgress × (sceneCount - 1)
activeIndex = round(sceneFloat)
localProgress = sceneFloat - floor(sceneFloat)
```

使用 `requestAnimationFrame` 合并滚动事件。React 只在 `activeIndex` 变化时更新语义状态；连续动画值写入舞台 CSS 自定义属性，避免每个滚动像素触发 React 重渲染。

每幕至少占一个视口的滚动距离。当前幕和相邻幕参与交叉淡化，其余幕隐藏并禁用指针事件。离开故事轨道后恢复普通文档流，页脚接在第七幕后方。

## 场景视觉与转场

沿用米白、深茶绿、朱砂点缀和现有原创 SVG 茶山/茶盏资产。七幕通过色块、裁切、编号和不同构图形成层次，不使用参考站素材。

- 进入：背景从 `scale(1.06)` 回落到 `1`，亮度和遮罩逐渐稳定；标题从下方约 32px 上移并淡入。
- 离开：标题向上约 24px 淡出，背景轻微放大或横移，为下一幕让位。
- 首页：主视觉占满舞台，搜索框和问茶入口保持可点击。
- 历史四幕：每幕只讲一个阶段，显示 `02—05` 大编号、章节标签、标题、说明和时间线进度；四幕使用同一结构但不同空间构图。
- 茶叶品类：绿茶和红茶卡片从画面两侧进入，档案数量读取 `publicItems`，卡片继续链接筛选后的茶品档案。
- 资料与联系：以深茶绿收尾，左右呈现资料边界与联系动作，并允许继续滚动到页脚。

右侧进度轨固定在舞台右侧安全区，包含七个点、当前幕短标签和 `aria-current="step"`。顶部导航与浅色/深色场景保持足够对比；必要时根据场景切换 `data-scene-tone`，只改变导航颜色和边框。

## 移动端模型

宽度不超过 600px 时取消长轨道和 `sticky` 重叠舞台。七个场景恢复为真实 DOM 文档流，每幕使用 `min-height: 100svh` 和 `scroll-snap-align: start`；页面容器使用 `scroll-snap-type: y proximity`，不使用强制 `mandatory` 吸附，不拦截触摸。

移动端隐藏右侧进度轨，继续使用底部四项导航。历史四幕依次出现，茶类卡片改为纵向排列。背景缩放和复杂位移关闭，只保留短距离淡入；表单控件、链接和文字均处于正常文档顺序。

## 可访问性与降级

- `prefers-reduced-motion: reduce` 时取消缩放、视差和平移动画，各幕直接切换透明度；移动端进一步取消吸附。
- 每个场景是带可见标题的 `section`，历史场景标题层级保持一致。
- 透明场景设置 `aria-hidden`；进入当前场景时不强制抢焦点。导航点击后仅在用户主动操作时把目标标题设为可编程焦点。
- JavaScript 不可用时，七个场景按普通纵向内容顺序显示。
- 使用 `100svh`，同时提供 `100vh` 回退，避免移动浏览器地址栏造成跳动。

## 组件边界

| 单元 | 职责 | 输入/输出 |
|---|---|---|
| `ScrollStory` | 计算故事轨道进度、活动幕与 CSS 变量；处理锚点映射 | 输入场景配置；输出当前幕、导航归属和滚动定位函数 |
| `StoryScene` | 提供统一的重叠层、语义 section 和转场属性 | 输入 ID、索引、色调、标题和场景内容 |
| `HistoryScene` | 渲染一个独立历史章节 | 输入编号、标签、标题、说明和视觉变体 |
| `StoryProgress` | 七点进度与直接定位 | 输入场景列表和 activeIndex；输出用户导航意图 |
| `CategoryScene` | 渲染绿茶与红茶入口 | 输入公开 `TeaItem[]`，按茶类计算数量 |
| `ReferenceContactScene` | 渲染资料说明与联系入口 | 无业务写入，只输出已有路由链接 |

问茶、茶品档案、详情、咨询和四套管理平台不改业务逻辑。首页搜索继续进入 `/catalog?q=`，“问茶 · 泡一杯”继续进入 `/qa`。

## 状态与 URL

`main.tsx` 只接收来自 `ScrollStory` 的导航归属，用于顶部和移动导航高亮。首页内部活动幕不写入浏览器历史，避免滚动时产生大量返回记录；只有用户点击顶部导航、进度点或外部深链接时更新 `?section=`。

刷新带 `section` 的地址时，在布局尺寸稳定后定位对应场景。浏览器前进/后退继续触发同一映射。商品上下架或来源状态导致公开茶品数量变化时，仅更新第六幕的数据，不重置滚动位置。

## 性能与错误处理

- 不增加 GSAP 或其他动画运行时依赖。
- 滚动监听为 passive，并由 `requestAnimationFrame` 合帧；卸载时取消事件与帧任务。
- 背景使用现有 SVG、CSS 渐变和轻量遮罩，不自动播放视频。
- 用 `ResizeObserver` 或窗口 resize 重新计算轨道尺寸；计算失败时退化为普通纵向布局。
- 空公开数据继续显示明确提示，分类入口不伪造档案数量。

## 验收标准

1. 桌面 1440×900：滚动时舞台保持全屏固定，七幕按顺序交叉转场，顶部导航和右侧进度同步。
2. 茶的历史四个章节各占独立滚动阶段，任一时刻只有当前章可交互和被辅助技术读取。
3. 桌面滚轮、触控板、PageDown、空格键和导航点击均可推进或定位，不出现滚动锁死。
4. `?section=history`、`categories` 和 `references-contact` 刷新后定位正确；浏览器返回正常。
5. 768px：布局保持可读，场景转场不遮挡导航和按钮。
6. 390×844：七幕为原生纵向吸附，历史四幕独立占屏，底部导航可用且无横向溢出。
7. 减少动画模式下无缩放和明显位移，内容与功能完整。
8. 茶品搜索、分类入口、问茶、咨询和后台入口仍可进入原有页面。
9. `npm run build` 通过，浏览器控制台无 error/warn。
