# 茶序 · 茶文化智能体交互原型

按已确认的「米白、深茶绿、朱砂」方案制作。用户端与管理后台通过可切换的 mock/live 服务运行，支持桌面、平板和移动端。

## 打开与启动

- 用户端：http://127.0.0.1:4173/
- 后台：http://127.0.0.1:4173/#/admin
- 入口源码：`src/main.tsx`

在本目录运行：

```powershell
npm ci
npm run dev
```

已安装依赖时只需 `npm run dev`。当前会话已启动服务；若地址无法打开，重新运行即可。构建检查使用 `npm run build`；构建结果位于 `dist`，需通过 HTTP 服务打开，不能直接双击 HTML。此地址仅供本机访问。

## API 运行模式

默认 `mock` 模式不发 HTTP 请求，公开端与后台共用同一契约状态机。复制 `.env.example` 为 `.env.local` 可以切换真实服务：

```dotenv
VITE_API_MODE=live
VITE_API_BASE_URL=http://127.0.0.1:8000/api/v1
```

只接受 `mock` 或 `live`。live 请求携带 cookie；写请求按需携带 CSRF、ETag 与幂等键，不在 localStorage 保存会话或 CSRF。live 后端不可达时显示服务不可用与重试入口，不读取 mock 种子补位。

## 版本快照

每次代码或设计画布改动完成并验证后，都要创建独立 Git 提交并推送到项目 GitHub 仓库。画布改动还需在项目根目录 `design-snapshots/` 保存 Figma/Penpot 链接、节点、版本说明和截图或导出物。完整规则见项目根目录 `AGENTS.md`，快照索引见 `VERSION_SNAPSHOTS.md`。

## 建议体验顺序

1. 在首页向下滚动浏览七幕内容：入口、茶史四章、茶叶品类、参考资料与联系我们。桌面端舞台固定，停止滚动后自动吸附到最近一幕，并且始终只显示当前幕；移动端按纵向页面邻近吸附。顶部或底部导航可直接定位相应章节。
2. 进入“问茶 · 泡一杯”，询问“西湖龙井怎么泡”或“祁门红茶第一泡要多久”，核对自动匹配的批次、参数与四步冲泡；完成后查看货源。
3. 申请样品，使用「填入示例内容」，主动勾选用途同意后提交，查看脱敏回执。
4. 在后台依次切换数据运营、客户审核、线索跟进和项目管理四套职能平台，观察导航、概览和待办变化。
5. 在「数据运营平台」的“内容与导入”页面编辑、导入并提交置顶草稿。
6. 在「客户审核平台」通过待审核内容；通过后系统自动发布，无需第二次发布操作。
7. 在「数据运营平台」或「项目管理平台」直接下架商品；切换到“已下架”后可免复审重新上架。即使演示来源已撤回，上架时也会同步恢复来源状态并立即显示到用户端。

公开目录、批次详情、问茶和咨询现已统一调用 `PublicApi`。问茶先调用 U11，仅在返回有效 `tea_id` 与 `tea_item_id` 时继续调用 U07；咨询按 U01 的用途版本提交 U12，并只展示服务返回的脱敏回执。

## 页面与交互范围

| 范围 | 页面与主要行为 |
|---|---|
| 用户端 | 七幕沉浸式滚动首页、桌面 Sticky 舞台与停滚吸附、单幕互斥显示、茶图与进度栏安全间距、移动端纵向吸附、章节导航、检索/茶类筛选、SKU 与批次详情、功效与适饮、资料来源弹窗、有效/失效货源 |
| 问茶与冲泡 | 泡法意图识别、茶品与批次自动填入、四步引导、专属/通用提示、参数调整、计时、完成反馈、无法确认、健康边界和离线降级 |
| 咨询 | 茶品咨询/样品申请、字段校验、主动同意、提交中状态、脱敏回执 |
| 数据运营 | 运营概览、草稿待办、内容编辑、CSV 导入校验与导入草稿、商品上下架；草稿置顶显示 |
| 客户审核 | 审核概览、审核待办、版本对比、退回修改、通过后自动发布 |
| 线索跟进 | 线索概览、线索筛选、状态跟进、脱敏导出 |
| 项目管理 | 项目概览、商品列表直接上下架/删除、账号权限、操作记录；下架关闭用户咨询，上架立即恢复用户端展示 |

四套后台页面现由 `src/features/admin/` 的会话、内容、审核和线索 hooks 驱动。演示身份切换会更新 mock 会话权限；内容保存、提交审核、审核、上下架、删除和线索跟进均携带当前 ETag 与新的幂等键。live 模式下身份由 A03 会话决定，界面不能任意切换；文件导入在 I01--I05 尚未联调时显示明确不可用状态，不下载或提交伪造结果。

## 与正式前后端开发的边界

接口规范仍以项目根目录 `茶文化智能体_前后端接口契约与Skill清单.md` 为准；本轮已同步问茶返回冲泡意图与茶品标识、回答后获取完整配方的约束，以及审核自动发布、商品上下架与逻辑删除约束。本原型验证页面流转与业务状态，不代表已经完成真实 HTTP 接口联调。

联调基础已落地：`src/api/` 统一解析 `/api/v1` 成功/错误信封并附带 cookie、`Idempotency-Key`、`X-CSRF-Token` 与 `If-Match`。通过 `VITE_API_MODE=mock|live` 选择本机契约模拟或真实后端；默认仍为本机演示模式，当前仓库未附带真实服务。

`src/api/mock/` 已将公开读取和后台命令建模为独立服务。它会阻断草稿、下架内容及来源撤回后的公开读取；重新上架保持已审核内容并恢复本次演示来源。该层用于验证页面接入前的契约和状态机，不会连接真实服务。

`src/api/createServices.ts` 按 `VITE_API_MODE` 选择 mock 或 live 适配器；live 端点严格使用 `/api/v1` 契约路径、snake_case 查询参数、cookie、CSRF、ETag 和调用方幂等键。公开目录、详情、问茶冲泡、咨询及四套后台页面均已迁移到 `AppServicesContext` 的领域服务。

- mock 领域数据保存在当前页面内存，刷新后恢复种子；界面审计和少量演示偏好保存在本机 localStorage，跨设备不共享。所有资料、供应主体、价格和线索均为演示。
- mock 问答是可控的契约响应，没有连接真实模型或检索服务；引用没有冒充真实研究资料。
- 联系方式在写入本机记录前脱敏；没有发送咨询，也没有支付或订单。
- mock 后台身份可切换以验证四类权限；live 身份由 A03 会话固定。正式授权、审稿身份隔离和审计持久化仍必须由后端执行。
- 当前编辑器可修改资料说明；完整结构化配方、资料附件、授权管理、账号创建等正式表单仍需后续开发。
- mock 提供可控的导入校验示例；live 下 I01--I05 未接入时明确禁用，不伪造上传或导入成功。XLSX、服务端文件存储和完整字段校验仍需后端。
- 演示版本对比仅保留当前公开内容与工作草稿；完整历史版本查询依照正式契约实现。
- 字体可从 Google Fonts 加载；无法联网时使用本机中文字体。茶盏与茶山插画为代码内的原创 SVG。

验证详情见 `验收记录.md`。最终截图为项目根目录 `output/playwright/19-api-mock-desktop.png`、`20-api-mock-mobile.png` 与 `21-api-live-unavailable.png`。
